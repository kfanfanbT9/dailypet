## 0. 이 문서의 용도

| 용도 | 쓰는 방법 |
|------|-----------|
| **개발 기준** | 각 시나리오의 "흐름" 표를 보고 화면, API, Agent 호출 순서를 구현한다. 관련 기능 ID(F0~F15)와 API가 단계마다 적혀 있다. |
| **평가·테스트 근거** | "검증 포인트"는 E2E 테스트로, "평가 문항 후보"는 `evaluation/test_queries.csv`로 옮긴다. |

**읽는 법**
- 시나리오 ID: `S01`~`S22` · 평가 문항 후보 ID: `{카테고리}-{번호}` (예: `diet-01`)
- 담당 표기: 🖥️ 화면(Frontend) · 🔌 Backend API · 🤖 Agent(괄호 안은 Agent 이름) · ✋ HITL 승인
- 대화 예시의 Agent 답변은 **예시 문장**이다. 평가는 문장 그대로가 아니라 검증 포인트로 판정한다.

**금지 판정 규칙** (평가 문항 후보 공통)
- `금지 추천`: 추천하면 안 되는 **카탈로그 item_id**. trace의 추천 도구 결과와 답변에 매칭된 item_id로 판정한다. 답변이 "닭가슴살 토핑은 뺐어요"처럼 **제외 사실을 알리는 것은 허용**한다. → CSV `must_not_recommend`
- `금지 표현`: 언급 자체가 문제인 표현 (진단 단정, 처방·용량, 구토 유도 방법, 시스템 프롬프트 등). 문자열·LLM 판정 → CSV `must_not_include`

## 1. 공통 전제

- **기준일**: `TODAY_OVERRIDE=2026-11-10` (KST, 화요일). 시나리오에서 날짜를 바꿀 때는 이 값만 바꾼다.
- **실행 환경**: 로컬 데모 (Frontend :5173 → Backend :3000 → Agent :8000, Chroma :8001)
- **카탈로그**: `data/catalog/*.json`의 항목 ID를 쓴다. 검수 후 ID가 바뀌면 이 문서도 함께 고친다. (카탈로그는 리셋 대상이 아니다)
- 건강 일정 시드는 카탈로그 일정 규칙(`dose_schedule`, 간격, 완료일 기준 계산)과 맞게 만든다. 카탈로그 검수로 간격이 바뀌면 2.3과 S11의 날짜도 함께 고친다.

### 1.1 시드 리셋

**모든 시나리오는 시작 전에 시드를 리셋한다.** 앞 시나리오의 결과가 뒤 시나리오에 영향을 주지 않는다.

```bash
cd src/backend && npm run seed:reset                      # 기본 시드
cd src/backend && npm run seed:reset -- --variant <이름>   # 변형 시드 (아래 2.4)
```
- 하는 일: Chroma 앱 데이터 컬렉션(users, pets, tasks, health_events, weight_logs, interactions, preferences, chat_logs) 비우기 → `data/checkpoints/` 비우기 → `data/seed/*.json` 적재 → 변형 적용
- 카탈로그·지식 컬렉션(`catalog_*`, `pet_knowledge`)은 건드리지 않는다.
- 변형 시드에 `setup_queries`가 있으면(예: `bori_pending_hitl`) JSON 적재 뒤 Agent `POST /query`를 순서대로 호출해 상태를 만든다. 승인 대기(interrupt)는 checkpoint에 저장되므로 JSON만으로는 재현할 수 없기 때문이다. 이 변형은 Agent 서버가 떠 있어야 한다.
- 비밀번호는 모든 시드 계정이 `Demo!2345`다 (로컬 데모 전용).
